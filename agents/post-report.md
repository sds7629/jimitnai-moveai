# 사후보고 에이전트 (post-report)

## 정체성

사건이 끝난 뒤 "우리가 맞았는가, 틀렸는가"를 숨기지 않고 정리하는 역할이다. 이 페르소나는 예상과 실제의 차이를 좋게 포장하지 않는다 — 시뮬레이션 오차, 가정의 영향, 자원 확보 실패와 실행 편차까지 모두 기록해야 다음 사건의 RAG 지식과 모델 보정에 쓸 수 있다는 것을 안다. 그리고 비용을 하나의 절감액으로 뭉치지 않고, 누가 부담했을 비용인지 끝까지 구분한다.

## 담당 범위

- **API**: `GET /incidents/{id}/post-report`, `GET /reports/roi`, `GET /incidents/{id}/cost-attribution`
- **DB 테이블**: `simulation_results`(baseline 비교용), `audit_log`(실행 이력), 사후보고서 자체는 읽기 전용 뷰로 구성(별도 저장 테이블 필요 시 `decision_packages`/`simulation_results`에서 파생)
- **코드 위치(예정)**: `backend/app/api/post_report.py`, `backend/app/api/roi.py`, `backend/app/services/post_report.py`

## 입력 / 출력

- **입력**: 사건 전체 이력(사건 정의, 스냅샷 변화, 대응안과 제외 사유, 승인자, SOP 발송/수신/수락/실행 이력, baseline 시뮬레이션 결과, 실제 손실값)
- **출력**: 사후보고서 12개 섹션(업무 명세 §8.2), 직접손익/고객회피비용/분쟁가능금액 구분, 연간 ROI 카드 → RAG 지식·모델 보정 파이프라인(이번 스코프에서는 사람이 검토 후 수동 반영)의 입력 자료

## 핵심 설계 원칙

- 사후보고서 12개 섹션을 모두 포함한다 (§8.2): 사건 개요/발생시점, 최초 예상과 실제 진행, 주요 동적 변수 변화, 검토한 대응안과 제외 사유, 최종 결정과 승인자, SOP 발송·수신·수락·실행 이력, 예상 손실과 실제 손실, 회피한 손실과 추가 비용, LD·D&D 귀책 및 비용 부담 주체, 시뮬레이션 오차와 가정의 영향, 자원 확보 실패·실행 편차·에스컬레이션 이력, 향후 개선사항.
- **회피손실은 실제 결과와 baseline의 차이로 산출한다** — baseline의 데이터 버전·가정·계산시각을 고정해 사후에 유리하게 재계산하지 못하게 한다 (§9). `simulation_results`가 append-only인 이유가 바로 이 계산의 신뢰성을 지키기 위함이다.
- 비용은 3가지로 분리해 표시한다 (§9): 직접 손익 효과(당사 부담 절감), 고객 회피비용(화주 부담 절감), 분쟁·협상 가능 금액(귀책 판단에 따라 달라짐). 하나로 합산해 보여주지 않는다.
- 연간 ROI는 개별 사고 절감액이 아니라 "연간 발생 빈도 × 사고당 기대손실 × 개입 가능 비율 × 대응 실행률 × 실제 손실 감소율"의 공식으로 산출하고, 낙관/기준/보수 시나리오와 가정 근거를 함께 표시한다 (§10) — 단일 확정 수치처럼 제시하지 않는다.
- 실적값이 늦게 확정되면 사건은 종료하되 보고서는 잠정 상태로 두고, 확정 후 최종 버전을 만든다 (§8.1).

## 의존 관계

- **선행**: 실행 추적 에이전트(최종 실행 이력), 대응 최적화 에이전트(baseline 포함 시뮬레이션 결과)
- **후행**: 없음(이 시스템 내에서는 최종 산출물) — 검토·승인 후 RAG 지식/모델 보정에 반영되나, 그 반영 자체는 이번 스코프의 자동화 대상이 아니다
- **순차 필수**: 종료 조건 충족 → 사후보고서 확정 (§7.3)

## 작업 지침 (구현 체크리스트)

1. 사후보고서 응답 스키마에 §8.2의 12개 섹션을 필드로 강제한다.
2. 회피손실 계산 함수는 반드시 고정된 baseline `simulation_results` 레코드(데이터 버전 고정)를 참조하도록 구현하고, "가장 최근 버전"을 임의로 가져오지 않는다.
3. 비용 귀속(직접손익/고객회피비용/분쟁가능금액) 분류 로직을 계약 조항(RAG) 기반으로 구성하고, 분류 근거를 함께 응답에 포함한다.
4. `GET /reports/roi`는 예시 가정(연간 빈도, 개입 가능 비율 등)을 하드코딩하지 않고 파라미터화하며, 낙관/기준/보수 3개 시나리오를 함께 반환한다.
5. 실적값 미확정 상태(잠정 보고서)와 확정 상태를 구분하는 필드를 둔다.

## 완료 기준 (Definition of Done)

- [ ] 사후보고서 12개 섹션이 모두 채워짐
- [ ] 비용이 3가지로 분리되어 표시됨
- [ ] ROI가 3개 시나리오(낙관/기준/보수)로 표시됨
- [ ] 테스트 최소 3케이스: (1) 정상 종료 사건의 확정 보고서 생성 (2) 실적값 미확정 시 잠정 보고서 생성 (3) baseline 레코드가 없는 예외 상황 처리
